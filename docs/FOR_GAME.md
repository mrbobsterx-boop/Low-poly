# Что нужно поменять в игре для моделей

Сюда записывается, если для моделей нужна правка игры (`mrbobsterx-boop/godot`). Автор перенесёт в чат игры.

**Как игра берёт модели сейчас** (2026-10-09, `scripts/world3d/view3d.gd`):
- файлы `assets/models/<id>_<вариант>_idle.glb` (копия из `export/` этого репозитория);
- ищет вариант объекта → любую модель этого объекта → иначе старая картинка;
- ставит по **высоте из ОС**, низ — на пол, перед (−Y в Blender) — к зрителю; ряд по глубине — по виду вещи;
- лампы на потолке — верх модели у потолка;
- сломанный объект — рассыпается на куски (поломку показывает игра);
- стены — из трёх слоёв (основа, линии, декор), см. `docs/TRIPO_KIT.md`.

Пока просьб нет.

## 2026-10-13 — ПРОСЬБА АВТОРА: редактор анимаций действий (в игре)

Сейчас анимация — просто одна из списка справа, это неудобно: автор не видит, как она выглядит именно в этом действии,
и не может закрепить «правильную». Нужен редактор **внутри игры**:

1. **Нажимаю на персонажа → «Анимации».** Открывается окно: слева — **действия** по группам (Основа, Быт, Работа,
   Общение, Бой, Состояния, Зомби, Мутант): «Идёт», «Открывает сундук», «Рубит дерево»… У каждого — значок: ⭐ закреплено
   / ○ не выбрано.
2. **Выбираю действие → справа кандидаты** (только подходящие по смыслу, 1–14 шт., не все 200). Нажимаю на кандидата —
   **персонаж сразу проигрывает её на месте, по кругу** (крупно, камера на персонаже; можно крутить, пауза, скорость
   ½×/1×/2×). Внизу — «Все анимации» (остальные, с поиском) — если среди кандидатов нет подходящей.
3. **⭐ — закрепить** эту анимацию за действием. Закреплённая — одна на действие; ⭐ на другой — заменяет. Повторное
   нажатие — снять.
4. **В игре:** когда персонаж делает действие (пошёл к сундуку → `walk`, открыл → `open_box`, рубит → `chop`…), игра
   берёт **закреплённую**. Не закреплено — запасная (первый кандидат) и пометка в редакторе «не проверено».
5. **Проверка в деле:** кнопка «Показать в действии» — персонаж в комнате выполняет цепочку (подойти → действие),
   чтобы увидеть, как анимация стыкуется с ходьбой (переходы 0,2–0,3 с).
6. **Хранение:** закреплённое — в `anim_actions.json` (поле `pinned` — `{"src": "mixamo", "anim": "walk"}`), чтобы не
   терялось и чат моделей мог это видеть. Можно одно закрепление на всех людей; позже — своё для фракции / зомби.

**Данные (этот репозиторий):** `export/anim/anim_actions.json` — 73 действия, у каждого `name` (по-русски), `group`,
`candidates` (`src` + `anim`), `pinned` (сейчас пусто — выбирает автор), и `unsorted` — анимации вне действий.
`sources` — какие файлы: `mixamo` → `anims_mixamo.glb` (106), `tripo_m` → `body_m_rig_anims.glb` (93),
`tripo_m_b` → `body_m_rig_b_anims.glb` (31), `tripo_f` → `body_f_rig_anims.glb` (76). Все — на скелете тел Tripo
(кости `mixamorig:…`), подходят ко всем 64 людям со скелетом. Имена анимаций Tripo — запросы автора (длинные), в
редакторе показывать начало + полностью во всплывающей подсказке.

## 2026-10-14 — анимации людей на одетых персонажах (ВАЖНО — переимпортировать)

Автор: «на одетых анимации хуже, в локте пережимает». Причины и что сделано:
1. **В анимациях было записано место каждой кости голого тела** (body_m_rig). Godot ставил кости одетого персонажа на эти
   места → плечи сужались, руки уходили в грудь и живот, полные персонажи вытягивались до роста голого тела. Теперь
   в `export/anim/*.glb` **только повороты костей + положение таза** — длины костей у каждого свои. Файлы перезаписаны
   (anims_mixamo 12,8 → 10 МБ, тела Tripo тоже).
2. **Локоть пережимало:** у скелетов Tripo в покое локти, колени и спина чуть согнуты, и при переносе этот изгиб
   прибавлялся к каждой анимации (+18° в локте). Исправлено — сгибы теперь ровно как в оригинале Mixamo.
3. **Нужно в игре** — `export/anim/char_fit.json`, по каждому персонажу:
   - `motion_scale` → `Skeleton3D.motion_scale` = значение для набора, из которого играет анимация
     (`mixamo`, `tripo_m`, `tripo_m_b`, `tripo_f`). Иначе таз — на высоте голого тела (ноги в полу / в воздухе).
   - `arm_spread_deg` (0–16°) → после анимации отвести плечи наружу, чтобы руки не проходили сквозь одежду и живот
     (анимации Mixamo — для худого голого тела). Пример (Godot 4.3+, дочерний узел `Skeleton3D`):
     ```gdscript
     extends SkeletonModifier3D
     @export var spread_deg := 0.0   # из char_fit.json → characters[id].arm_spread_deg
     func _process_modification() -> void:
         var sk := get_skeleton()
         for i in sk.get_bone_count():
             var n := sk.get_bone_name(i)
             var s := 1.0 if n.ends_with("LeftArm") else (-1.0 if n.ends_with("RightArm") else 0.0)
             if s == 0.0:
                 continue
             var gp := sk.get_bone_global_pose(i)
             gp.basis = Basis(Vector3(0, 0, 1), deg_to_rad(spread_deg * s)) * gp.basis   # ось «вперёд» модели (+Z)
             sk.set_bone_global_pose(i, gp)
     ```
   - Не включать в импорте Retarget / BoneMap / Rest Fixer (как и раньше).
- Сравнение «было / стало»: `renders/_review/anims_clothed_fix_2026-10-14.jpg`. Проверка кадров «как в Godot» —
  `tools/anim_check.py`.

Обычные `export/<имя>_idle.glb` не тронуты — новые лежат отдельно: `export/parts/<имя>.glb`.

Как устроен файл:
- узел `body` — корпус (за дверью уже есть проём и пустота внутри; у машин — простые сиденья и панель);
- остальные узлы — подвижные части: `door`, `door_l` / `door_r`, `lid`, `hood`, `trunk`, `tailgate`,
  `door_front_1` (левый борт, перед), `door_back_1` (правый борт), `door_slide_front`, `cap`, `barrier`, `lever`…;
- **точка каждой части уже стоит на петле** — достаточно повернуть узел (без пересчёта центра).

Как открывать — `export/parts/open_parts.json` (координаты Godot, Y вверх):
- `pivot` — где петля (это и есть позиция узла);
- `rotate_axis` + `rotate_deg` — повернуть узел вокруг этой оси на столько градусов от закрытого положения;
- `move` — сдвинуть на столько метров (раздвижные двери вагонов, крышки бочек, гаражные ворота).

Предложение по коду (пример, не обязателен):
```gdscript
# open: 0.0 — закрыто, 1.0 — открыто
func set_open(model: Node3D, info: Array, open: float) -> void:
    for p in info:
        var n: Node3D = model.find_child(p.node, true, false)
        var base := Vector3(p.pivot[0], p.pivot[1], p.pivot[2])
        n.position = base
        n.basis = Basis.IDENTITY
        if p.has("rotate_deg"):
            var ax := Vector3(p.rotate_axis[0], p.rotate_axis[1], p.rotate_axis[2]).normalized()
            n.basis = Basis(ax, deg_to_rad(p.rotate_deg * open))
        if p.has("move"):
            n.position = base + Vector3(p.move[0], p.move[1], p.move[2]) * open
```
Для физики: части — отдельные узлы, им можно дать `RigidBody3D` + `HingeJoint3D` (ось — `rotate_axis`, точка —
`pivot`, предел — `rotate_deg`) или `SliderJoint3D` (для `move`). Колодец (`windlass`) — ворот крутится по кругу,
насос (`lever`) — рычаг качается.

В `export/parts/open_parts.json` у колеса: `"wheel": true`, `radius` (м), `spin_axis` (ось вращения, Godot).
Крутить: угол += скорость_м_с / radius × delta (вокруг `spin_axis`); разгон и торможение — просто плавно менять
скорость. Передние колёса машин можно ещё поворачивать вокруг вертикали (руль) — это узлы с бо́льшим X у машин,
у которых перед к +X (см. поле `front` в `tripo/open_parts.json`: 1 — перед к +X Blender, −1 — к −X).
```gdscript
func spin_wheels(model: Node3D, info: Array, speed_mps: float, delta: float) -> void:
    for p in info:
        if p.get("wheel", false):
            var n: Node3D = model.find_child(p.node, true, false)
            var ax := Vector3(p.spin_axis[0], p.spin_axis[1], p.spin_axis[2])
            n.rotate_object_local(ax, speed_mps / p.radius * delta)
```

## 2026-10-16 — фон за улицей из моделей (`export/backdrop/`)

Замена коробок и конусов в `scripts/world3d/backdrop.gd` на модели. Всё описано в **`export/backdrop/backdrop.json`**,
переход делает чат игры по этому файлу (код игры здесь не менялся).

**Что есть.** 8 биомов, как в `Backdrop.BIOMES`: forest, field, desert, swamp, snow, wasteland, city, industrial
(всего 76 вещей), у каждого — 2 ленты дальнего плана и 3 птицы.

**Файлы.**
- Вещь: `bg_<биом>_<вид>_<номер>_lod0.glb` / `_lod1.glb` / `_lod2.glb`:
  - `lod0` — ближе −12 м (до 1500 тр., дома до 3000);
  - `lod1` — −12…−20 м (до 500);
  - `lod2` — дальше −20 м (до 150, силуэт: две скрещённые плоскости, цвет в вершинах, двусторонние).
  Уровни совпадают с ярусами `tier` в `backdrop.gd` (0 / 1 / 2).
- Лента горизонта: `bg_<биом>_ridge_<1|2>_idle.glb` — ширина 40 м, края совпадают (ставить подряд по X, хоть
  через одну разную), глубина 30 м: передний край у точки опоры, лента уходит в −Z. Ставить за фоном
  (около Z −32…−80), цвет в вершинах, без текстур.
- Птицы: `bg_bird_<crow|seagull|pigeon>_idle.glb`, анимация **`bird_flap`** (зациклить), для стай над фоном.

**Поля `backdrop.json`** (по биому `items` и `ridges`):
- `id`, `kind` (вид, как ключи в `BIOMES`: pine, leaf, bush, building, factory, ruin, pole, chimney…);
- `size` [ш, в, г] м; `lods` — 3 файла; `tris`;
- `per_10m2` — сколько штук на 10 м² (густота);
- `min_depth` — м вглубь от начала фона (`Z_FROM`), ближе не ставить (крупное — дальше, как словарь `near`);
- `rotate` — можно ли крутить вокруг вертикали (дома/заводы — нет, смотрят на камеру);
- `sway` — есть узел **`sway`** (крона, куст, камыш, флаг): качать его ветром, остальное (`body`) стоит.
  Шейдеру `ModelFx` маска не нужна: качается весь узел `sway`;
- `smoke` — точки дыма `[x, y, z]` (Godot, от точки опоры); в моделях это пустые узлы **`smoke_1`, `smoke_2`…**
  у выхода трубы — дым делает игра;
- `window_lit` — окна отдельным материалом **`window_lit`** (днём тёмные; ночью — включить свечение/emission);
- у лент — `width` 40, `depth` 30, `height`.

**Как в игре.** Точка опоры — низ по центру, перед смотрит на камеру (+Z Godot), 1 ед. = 1 м, без блеска,
текстуры 512 (lod0) / 256 (lod1), дальние — без текстур. Дымку (туман `FOG`) и снег зимой даёт игра, как сейчас
(снег в моделях есть только у биома snow). Размеры домов и заводов — как у нынешних коробок (дома 8–13 м, ширина
до 10 м).

**Потом заменятся.** Кактусы, стог, кочка, мостки, столбы, труба, баки, опора ЛЭП сделаны кодом — когда автор
пришлёт модели Tripo (`docs/TRIPO_OBJECTS.md` раздел 12, папка «23 Фон»), файлы перезапишутся с теми же именами.
