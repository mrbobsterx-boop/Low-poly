# Правила для работы в этом репозитории

Это репозиторий **3D-моделей (Blender, low-poly)** для игры «Shelter». Сначала прочитай `README.md` — там цель,
два пути (рендер в 2D или 3D в игре) и обязательные правила моделей. Какие картинки делать — `docs/IMAGES.md`
(обязательно перед любым рендером). Мебель в комнаты не впекать: комната — пустая оболочка, предметы — отдельно.

- Игра — репозиторий `mrbobsterx-boop/godot` (главный документ — `GAME_MAP.md`, раздел 9 — требования к картинкам).
  Код игры **здесь не меняется**; если для моделей нужна правка игры — записать в `docs/FOR_GAME.md`, автор перенесёт.
- Объекты, их id и размеры — только из ОС (`mrbobsterx-boop/object-constructor`). Новый объект сначала заводят в ОС,
  потом делают модель. **Что делать — по плану ОС** (`tools/object-plan`): выгрузка `node tools/sync_plan.js <ОС>` →
  `docs/plan.json`, чек-лист `python3 tools/plan_status.py` → `docs/PLAN.md`.
- **Правила автора по плану:** только `idle`, каждый вариант — отдельная модель `<id>_<вариант>_idle` (вариант —
  транслит названия из плана, как в ОС); «сломанные/испорченные» варианты и состояния (открыт, занят, пустой) — не
  делать; размер — из ОС, если в плане другой — спросить автора; старые картинки ОС — **не образец стиля**;
  размер варианта, явно другой по природе (кресло, канистра 5 л), — решаю сам и пишу в `docs/DEVIATIONS.md`
  (образец — `docs/ref/style/`, `docs/STYLE.md`).
- **Сломанный вид не рисуем отдельно:** общая функция `break_parts()` в `models/_lib.py` (ножки, дверца, крышка,
  наклон + обломки и сколы); включается одним параметром `make(..., broken=...)` и только для предметов, которые в ОС
  ломаются (`docs/breakable.json`, `tools/sync_breakable.py`). Сейчас выключено (`MAKE_BROKEN = False`) — только idle.
  Промежуточные стадии и анимацию поломки делает игра.
- Модели можно делать скриптом Blender (Python, `bpy`): скрипт кладётся рядом — `models/<категория>/<id>.py`,
  чтобы модель можно было пересобрать. Запуск: `python3 models/<категория>/<id>.py` (Blender как модуль `bpy` —
  в облачной сессии ставится сам при старте) или `blender -b -P models/<категория>/<id>.py`. Рендер — через
  `render/_template.py` (`setup_scene()`, `render_pair()`), цвета — `palette/palette.md`. Модели собираются из
  заготовок `models/_lib.py` (`box`, `cyl`, `make`); проверка глазами — `render/_preview.py`, комната — `render/_mockup.py`.
- Перед отправкой проверить: масштаб (1 = 1 м, размеры как в `docs/OBJECTS.md`), origin внизу по центру,
  «перед» к −Y, общая палитра, **чистая модель** (без запечённого света/теней/грязи/фильтров — README, правило 10), лимит треугольников, экспорт `.glb` в `export/`.
- Язык общения и документов — русский. Имена людей, городов, фракций — западные.
- Автор игры — не программист: объяснять просто, по пунктам. Числа и решения по стилю — согласовывать с автором.
- Каждое изменение — строка в `docs/LOG.md` (дата, что сделано).
