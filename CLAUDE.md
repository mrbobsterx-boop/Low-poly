# Правила для работы в этом репозитории

Это репозиторий **3D-моделей для игры «Shelter»**. С 2026-10-09 (решение автора) игра показывает мир **в настоящем 3D**,
модели делает **автор в Tripo**, а здесь их **обрабатывают** и отдают в игру. Сначала прочитай `README.md`, потом
**`docs/TRIPO.md`** — главный документ: что делает автор, что делаешь ты, что делает игра.

**Твоя работа — обработка моделей из `tripo/`** скриптом `tools/tripo_process.py` (Blender как модуль `bpy`):
поворот передом к −Y, точка опоры внизу по центру, высота из ОС, облегчение сетки, текстуры 1024, без блеска →
`export/<id>_<вариант>_idle.glb` + отчёт `docs/TRIPO_REPORT.md` + лист превью со светом. Подробно — `docs/TRIPO.md`.

**Не делать:** рендеры в картинки, карты нормалей, палитру, модели «из коробок» скриптом, отдельные сломанные и иконки.
Всё это — старый путь, лежит в `archive/` только для справки.

- Игра — репозиторий `mrbobsterx-boop/godot` (главный документ — `GAME_MAP.md`; 3D-показ — `scripts/world3d/view3d.gd`).
  Код игры **здесь не меняется**; если для моделей нужна правка игры — записать в `docs/FOR_GAME.md`, автор перенесёт.
- Объекты, их id, варианты и размеры — только из ОС (`mrbobsterx-boop/object-constructor`, план — `tools/object-plan`):
  выгрузка `node tools/sync_plan.js <ОС>` → `docs/plan.json`, чек-лист `python3 tools/plan_status.py` → `docs/PLAN.md`.
- **Правила автора:** только обычный вид (`idle`); **сначала по одному варианту на объект** (~180), остальные — потом;
  «сломанные / испорченные» варианты и состояния (открыт, занят, пустой) — не делать: поломку и состояния показывает игра.
  Размер — из ОС; ширина модели сильно другая (> 15 %) — решаю сам и пишу в `docs/DEVIATIONS.md`.
- Масштаб 1 единица = 1 м; «перед» — к −Y в Blender (в игре — к зрителю); экспорт glTF 2.0 `.glb`, +Y up, текстуры внутри.
- Лимит треугольников: мелкое ≤ 3 000, мебель ≤ 8 000, крупное ≤ 15 000. Файл ≤ 3 МБ. Проверка — лист превью со светом.
- Новые решения по стилю (цветовой фильтр, лимиты) — сначала показать автору на 3 моделях, без его «да» на все не применять.
- Язык общения и документов — русский. Имена людей, городов, фракций — западные.
- Автор игры — не программист: объяснять просто, по пунктам.
- Каждое изменение — строка в `docs/LOG.md` (дата, что сделано).
