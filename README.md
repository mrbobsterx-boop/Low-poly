# Low-poly — 3D-модели для игры «Shelter»

Здесь делаются **low-poly 3D-модели в Blender** для игры про выживание в бункере после катастрофы.
Сама игра — в соседнем репозитории **[mrbobsterx-boop/godot](https://github.com/mrbobsterx-boop/godot)** (Godot 4.7).
Данные объектов (что есть в игре, размеры, действия) — в **Object Constructor (ОС)**: [mrbobsterx-boop/object-constructor](https://github.com/mrbobsterx-boop/object-constructor).

**Что делать сейчас и дальше — по шагам: [`STEPS.md`](STEPS.md).**

## Зачем

Сейчас в игре — плоские PNG-картинки (часть объектов вообще без картинок). Цель — единый стиль **low-poly**
(как на референсе: бункер в разрезе на закате, тёплый свет ламп, рубленые грани, руины города вдали) и **глубина** —
комнаты видны как коробка в разрезе, вещи стоят в несколько рядов.

## Два пути (решение ещё не принято)

| | **А. Рендер в 2D** | **Б. 3D в игре** |
|---|---|---|
| Что попадает в игру | PNG-рендеры моделей (вид сбоку) + карты нормалей | Сами модели `.glb` |
| Переделка игры | Малая: картинки заменяются, логика не трогается | Большая: всё отображение мира переписывается на 3D (логика остаётся) |
| Плюсы | Быстро, можно постепенно | Живой свет и тени, анимации скелетом, одежда видна на человеке |

**Модели делаем так, чтобы годились для обоих путей** (правила ниже). Сначала — **проба**: одна комната бункера,
один человек, 5–6 предметов, лампа. По пробе решаем, какой путь.

## Правила моделей (обязательно)

1. **Масштаб: 1 единица Blender = 1 метр.** Размеры — как в ОС (таблица `docs/OBJECTS.md`, ширина × высота в см).
   В игре 1 м = 100 px, поэтому неправильный масштаб сразу виден.
2. **Оси:** вид сбоку — камера смотрит вдоль **+Y** (на объект спереди). X — вправо (ширина), Z — вверх (высота), Y — глубина.
   «Перед» объекта (дверца шкафа, экран плиты) смотрит на **−Y**, к камере.
3. **Точка опоры (origin)** — **внизу по центру**, на полу (Z = 0). Висящее на стене (лампа, полка, плакат) — origin
   в точке крепления, а «спина» в плоскости Y = 0.
4. **Low-poly:** рубленые грани, плоское (flat) затенение; у мебели, металла и техники плоскости **ровные**, рёбра чёткие (фаска 1 сегмент);
   неровности (`roughen()`) — только у камня, земли, обломков, ткани, еды, растений (`docs/QUALITY.md`), износ — формой и пятнами палитры (`spot()`). Ориентир по треугольникам —
   в `docs/QUALITY.md` (мелкий до 1 500, мебель до 6 000, крупное до 12 000, модуль комнаты до 25 000)
   (после референса автора: предметы подробнее — ручки, ящики, банки; ориентир автора — 50–5000 на предмет).
5. **Цвет — одна общая палитра** (`palette/palette.png`, 8 × 5 квадратов, список — `palette/palette.md`): у всех
   моделей один материал с этой текстурой, цвет задаётся UV-развёрткой на нужный квадрат палитры. В скриптах цвет
   указывается **только по имени** (`paint(obj, "rust")` из `render/_template.py`) — тогда палитру можно менять и
   расширять, а модели перекрашиваются простой пересборкой. Без своих текстур у каждого объекта.
   Светящееся (лампа, огонь печи, экран) — отдельный материал «emission».
6. **Имя = id из игры, одна схема для всего:** `<id>_<вариация>_<состояние>` — модели, `.glb` и рендеры.
   Вариация — как в ОС, русскими словами латиницей (`zheleznaya_koyka`), состояние — `idle` / `broken`.
   Скрипт модели — `models/<категория>/<id>.py` (собирает все вариации и состояния), экспорт —
   `export/<id>_<вариация>_<состояние>.glb`. Двойного подчёркивания нет. Список id — `docs/OBJECTS.md`.
7. **Экспорт glTF 2.0 (.glb):** перед экспортом Apply All Transforms; галочка «+Y Up» — включена (как по умолчанию,
   Godot ждёт именно так); материалы — да; анимации — только у людей и животных.
8. **Люди и животные:** один общий скелет на всех людей (`models/character/_rig_human.blend`), один — на собак.
   Анимации (по имени): `idle`, `walk`, `work`, `sleep`, `sit`, `hit`, `hurt`, `die`, `carry`. Одежда и
   снаряжение — отдельные модели, надеваются на кости (для пути Б).
9. **Модули бункера** — коробки в разрезе: задняя стена и пол, без передней стены; перекрытие между этажами — **1 м**
   (так в игре: этаж = 3 м + 1 м). Высота комнаты **3 м**, глубина **3 м**. Ширина — **сегмент 512 см, бесшовный**
   (игра повторяет его на всю ширину комнаты) + края 50 см. Подробно — `docs/IMAGES.md`, раздел 2.
10. **Без запечённого направленного света — но не «голый» цвет.** Свет, тени от предметов, блики, свечение, туман,
    цветокоррекция — делает **Godot**. В модели **нужны**: переход оттенков (градиентная палитра), мягкое затенение в
    щелях (AO), потёртости на рёбрах, грязь у пола, декали (таблички, трафареты, полосы). Подробно — **`docs/QUALITY.md`**
    (решение автора 2026-10-09; заменяет прежнее «только ровный цвет»).

    Картинки-образцы из ОС (`docs/ref/`, список — `docs/REFS.md`) — **не образец стиля**, только форма и пропорции.

## Для пути А (рендер)

- Сцена-шаблон `render/_template.blend`: ортографическая камера, наклон сверху **12°**, прозрачный фон.
  **Все** объекты рендерятся одной камерой — иначе ломается глубина.
- **Без света** (правило 10): в рендер идёт только чистый цвет — на время рендера каждый материал подменяется
  свечением (Emission) того же цвета, без теней. Цветовое преобразование — **Standard** (не Filmic / AgX), иначе
  цвета палитры уедут. Движок — Cycles на процессоре (видеокарта не нужна).
- **Вертикаль растянута на 1/cos 12° (+2,2 %)** — так 1 м по вертикали = ровно 200 px, как в игре (этаж 400 px без
  щелей), а глубина 1 м поднимает картинку на tan 12° ≈ 21 см. Делается настройкой пикселя камеры, модель не меняется.
- **Объём даёт карта нормалей**, а свет — **Godot** (решение автора, 2026-10-08): в игре будет общий свет
  «солнце / небо» (направление и цвет меняются со временем суток и погодой) плюс лампы, огонь, фонарь. Все они
  освещают картинку по карте нормалей — грани low-poly видны и днём, и ночью. Без карты нормалей картинка будет плоской.
- **Карта нормалей — как ждёт Godot:** в пространстве камеры, цвет = нормаль × 0,5 + 0,5; **R** — вправо,
  **G — вверх** (формат OpenGL, «зелёный вверх»), **B** — на камеру. Плоская стена, смотрящая на камеру, —
  цвет (128, 128, 255). Делается в шаблоне материалом-заменой (Geometry → Normal → Vector Transform мир → камера →
  Z × −1, потому что в Cycles ось Z камеры смотрит от камеры → ×0,5 + 0,5 → Emission), без цветокоррекции (Raw).
  Проверка на кубе (`renders/_test/`): перед — (128, 101, 252), верх — (128, 252, 154), левый бок R ≈ 37, правый ≈ 218.
- Рендер: PNG с альфой, 200 px на метр (вдвое больше игрового — для чёткости). Обе картинки — одного размера,
  пиксель в пиксель.
- Результат — `renders/<категория>/<id>_<вариация>_<состояние>.png` (цвет) и тот же файл с `_n` (нормали); подробно — `docs/IMAGES.md`.

**Какие картинки делать (размеры, имена, состояния, комнаты, фасады, персонажи) — `docs/IMAGES.md`.**

## Структура

```
docs/OBJECTS.md      — все объекты игры: id, название, размер, есть ли 2D, готова ли модель (☐ → ☑)
docs/IMAGES.md       — какие картинки делать: размеры, имена, состояния, комнаты-оболочки, фасады, персонажи
layouts/             — готовые расстановки комнат (какой предмет где стоит), JSON
docs/STYLE.md        — стиль: цвета, свет, настроение (заполняется по ходу)
docs/REFS.md         — картинки-образцы из ОС: какая у какого объекта, сложность модели
docs/ref/<категория>/<id>.png — сами картинки-образцы
STEPS.md             — что делать по шагам (для автора)
palette/             — общая палитра: palette.png (текстура), palette.md (список), _palette.py (собирает)
models/<категория>/  — скрипты моделей <id>.py + <id>.blend (посмотреть в Blender); общие заготовки — models/_lib.py
render/_preview.py   — лист «рендер / со светом / образец ОС»; render/_mockup.py — комната из картинок по расстановке
export/              — .glb для игры
render/              — шаблон рендера (путь А): _template.py собирает _template.blend и проверочный куб
renders/             — PNG-рендеры (путь А)
```
