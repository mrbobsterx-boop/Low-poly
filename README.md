# Low-poly — 3D-модели для игры «Shelter»

Здесь делаются **low-poly 3D-модели в Blender** для игры про выживание в бункере после катастрофы.
Сама игра — в соседнем репозитории **[mrbobsterx-boop/godot](https://github.com/mrbobsterx-boop/godot)** (Godot 4.7).
Данные объектов (что есть в игре, размеры, действия) — в **Object Constructor (ОС)**: [mrbobsterx-boop/object-constructor](https://github.com/mrbobsterx-boop/object-constructor).

## Зачем

Сейчас в игре — плоские PNG-картинки (часть объектов вообще без картинок). Цель — единый стиль **low-poly**
(как на референсе: бункер в разрезе на закате, тёплый свет ламп, рубленые грани, руины города вдали) и **глубина** —
комнаты видны как коробка в разрезе, вещи стоят в несколько рядов.

## Два пути (решение ещё не принято)

| | **А. Рендер в 2D** | **Б. 3D в игре** |
|---|---|---|
| Что попадает в игру | PNG-рендеры моделей (вид сбоку) + карты нормалей | Сами модели `.glb` |
| Переделка игры | Малая: картинки заменяются, логика не трогается | Большая: всё отображение мира переписывается на 3D (логика остаётся) |
| Плюсы | Быстро, можно постепенно | Живой свет и тени, анимации скелетом, одежда видна на человеке |

**Модели делаем так, чтобы годились для обоих путей** (правила ниже). Сначала — **проба**: одна комната бункера,
один человек, 5–6 предметов, лампа. По пробе решаем, какой путь.

## Правила моделей (обязательно)

1. **Масштаб: 1 единица Blender = 1 метр.** Размеры — как в ОС (таблица `docs/OBJECTS.md`, ширина × высота в см).
   В игре 1 м = 100 px, поэтому неправильный масштаб сразу виден.
2. **Оси:** вид сбоку — камера смотрит вдоль **+Y** (на объект спереди). X — вправо (ширина), Z — вверх (высота), Y — глубина.
   «Перед» объекта (дверца шкафа, экран плиты) смотрит на **−Y**, к камере.
3. **Точка опоры (origin)** — **внизу по центру**, на полу (Z = 0). Висящее на стене (лампа, полка, плакат) — origin
   в точке крепления, а «спина» в плоскости Y = 0.
4. **Low-poly:** рубленые грани, плоское (flat) затенение, без мелких деталей. Ориентир по треугольникам:
   мелкий предмет — до 300, мебель — до 1 500, человек — до 3 000, здание/модуль комнаты — до 8 000.
5. **Цвет — одна общая палитра** (`palette/palette.png`, текстура-градиент): у всех моделей один материал с этой
   текстурой, цвет задаётся UV-разверткой на нужный квадрат палитры. Без своих текстур у каждого объекта.
   Светящееся (лампа, огонь печи, экран) — отдельный материал «emission».
6. **Имя = id из игры.** `models/<категория>/<id>.blend`, экспорт — `export/<id>.glb`. Список id — `docs/OBJECTS.md`.
   Варианты: `<id>__broken` (сломанный, если в ОС есть), `<id>__v2` (второй вид).
7. **Экспорт glTF 2.0 (.glb):** перед экспортом Apply All Transforms; галочка «+Y Up» — включена (как по умолчанию,
   Godot ждёт именно так); материалы — да; анимации — только у людей и животных.
8. **Люди и животные:** один общий скелет на всех людей (`models/character/_rig_human.blend`), один — на собак.
   Анимации (по имени): `idle`, `walk`, `work`, `sleep`, `sit`, `hit`, `hurt`, `die`, `carry`. Одежда и
   снаряжение — отдельные модели, надеваются на кости (для пути Б).
9. **Модули бункера** — коробки в разрезе: задняя стена, пол, потолок (перекрытие 0,3 м), без передней стены.
   Стандарт: высота комнаты **3 м**, глубина **3 м**, ширина кратна **1 м**.

## Для пути А (рендер)

- Сцена-шаблон `render/_template.blend`: ортографическая камера, наклон сверху **12°**, свет слева-сверху,
  прозрачный фон. **Все** объекты рендерятся одной камерой и одним светом — иначе ломается глубина.
- Рендер: PNG с альфой, 200 px на метр (вдвое больше игрового — для чёткости), + проход Normal (карта нормалей).
- Результат — `renders/<id>.png` и `renders/<id>_n.png`.

## Порядок работы

1. Проба: `bunker_room_3m` (модуль комнаты — новый объект, сначала завести в ОС), `survivor_base` (с `idle` и `walk`), `bed_single`, `table_wood`, `chair_wood`,
   `locker_metal`, `stove_heat`, `lamp_ceiling`.
2. Отдать в игру → посмотреть на Steam Deck → решить путь А или Б.
3. Дальше — по частоте на экране: люди и существа → мебель бункера → хранилища → предметы → улица и дома.

## Структура

```
docs/OBJECTS.md      — все объекты игры: id, название, размер, есть ли 2D, готова ли модель (☐ → ☑)
docs/STYLE.md        — стиль: цвета, свет, настроение (заполняется по ходу)
palette/             — общая палитра-текстура
models/<категория>/  — исходники .blend
export/              — .glb для игры
render/              — шаблон рендера (путь А)
renders/             — PNG-рендеры (путь А)
```
