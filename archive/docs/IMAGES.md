# Какие картинки делать (путь А: рендер в 2D)

Основа — раздел 9 `GAME_MAP.md` игры (требования к картинкам). Здесь — то же, но для рендеров из Blender.
Всё, что не подходит под эти правила, в игру не встанет или встанет криво.

## 0. Общее для всех рендеров

| Параметр | Значение |
|---|---|
| Масштаб игры | **1 см = 1 px** (1 м = 100 px). Рендерим **вдвое крупнее: 200 px на метр** — для всех одинаково |
| Вертикаль | Растянута на 1/cos 12°: **1 м по вертикали = ровно 200 px**, глубина 1 м поднимает картинку на **21 см** (tan 12°) |
| Камера | Одна на всех: ортографическая, вид сбоку, наклон сверху **12°** (`render/_template.blend`). Никакой перспективы |
| Свет | **Нет** (правило 10 README): только чистый цвет палитры, цветокоррекция **Standard** |
| Пара файлов | `<имя>.png` — цвет (с прозрачностью) и `<имя>_n.png` — карта нормалей (формат — README, «Для пути А»). Один размер, пиксель в пиксель |
| Фон | Прозрачный (кроме комнат-оболочек и дальних слоёв улицы — там непрозрачно) |
| Направление | Персонажи и животные смотрят **вправо** (влево игра отражает сама). Предметы — «передом» к камере |
| Опора | **Низ картинки = пол / земля.** Ножки стоят ровно на нижнем крае, по центру картинки |
| Поля | Предметы — **без пустых полей** вокруг (обрезать по контуру). Комнаты и фоны — точно по размеру |
| Имена | Латиница, id из игры: `<id>_<вариация>_<состояние>.png`, вариация — **как в ОС** (русские слова латиницей). Пример: `bed_single_zheleznaya_koyka_idle.png` |
| Куда | `renders/<категория>/…` — дальше автор переносит в ОС (`assets/refs/<категория>/`) и синхронизирует с игрой |

## 1. Предметы, мебель, приборы, хранилища, растения (из ОС)

- **Масштаб один — 200 px/м, картинка может быть выше числа из ОС** (решение автора): камера видит ещё и верх
  предмета. Высота картинки = высота + глубина × 0,21. Шкаф 180 см глубиной 50 см → 180 + 11 = 191 см → 382 px.
  **Игра берёт размер из самой картинки** (пиксели ÷ 2), а не из высоты в ОС (`docs/FOR_GAME.md`).
  Модель строится по размерам ОС.
- Состояния — **сейчас только `idle`** (решение автора). `broken` при необходимости делается автоматически общей
  функцией `break_parts()` (только для предметов, которые в ОС ломаются); промежуточные стадии и анимацию — игра.
  Состояния вроде «открыт», «занят» — пока не делаем. **Иконку не делать:** игра берёт её из `idle`.
- Вариации — **все варианты из плана ОС**, каждый отдельно; имя — транслит названия варианта из плана, как в ОС
  (`derevyannyy`, `zheleznaya_koyka`…, список — `docs/PLAN.md`): игра выбирает случайную.
- **Висящее** (лампа, часы, полка, щиток, окно, выключатель): картинка — только сама вещь; где висеть, задаёт ОС
  (`custom.mount` = `wall` / `ceiling`).
- Выше **270 см** в комнату не встанет (под потолком). Уличное — можно выше.
- Ничего лишнего в кадре: без пола под предметом, без стены за ним, без теней.

## 2. Комнаты — «оболочки» (новое, для глубины)

**Комната = пустая коробка + отдельные предметы.** Мебель в комнату **не впекаем**: каждую кровать, шкаф, плиту
человек в игре обыскивает, берёт, переносит, ломает, в них лежат вещи. Поэтому оболочка — только стены, пол
и «неживой» декор.

- Что в оболочке: задняя стена, видимая полоса пола (наклон 12°), трубы, кабели, вентиляция,
  трещины, плитка, обои, плакаты, следы протечек — всё, с чем нельзя ничего сделать.
- **Полосы потолка нет:** камера смотрит сверху и потолок снизу не видит. Верх комнаты — срез перекрытия (`slab_*`).
- Что **не** в оболочке: мебель, хранилища, приборы, лампы, двери, окна, лестницы — это предметы ОС (раздел 1).
- Размеры (в игре; рендер ×2):
  - **Сегмент** `<тип>_<вариация>_<состояние>_mid.png` — **512 × 364 см** (1024 × 728 px), бесшовный по
    горизонтали (игра повторяет его на всю ширину комнаты 5–8 м). Посчитано шаблоном: стена 300 см + видимая
    полоса пола 64 см (глубина 3 м × 0,21). **Низ картинки = передний край пола**, стена начинается на 64 см выше.
  - **Края** `…_left.png` и `…_right.png` — срез боковой стены коробки, **50 × 364 см**.
  - **Перекрытие** между этажами `slab_bunker_…png`, `slab_house_…png` — **512 × 100 см**, бесшовное (толстая
    рамка разреза: бетон, балки, арматура) — это передний срез перекрытия 1 м.
  - **Как стыкуется** (от переднего края пола этажа): оболочка 0–364 см, перекрытие поверх неё 300–400 см
    (закрывает верхние 64 см задней стены — так и в жизни), следующий этаж — с 400 см. Щелей нет.
  - **Ряды предметов** поднимаются на полосу пола: `front` (0,5 м от края) — на 11 см, `mid` (1,5 м) — на 32 см,
    `back` (2,5 м) — на 53 см (в игре: px = см). Низ картинки предмета — на этой высоте над линией пола.
  - **Висящее под потолком** (`row: ceiling`, лампы): верх картинки — на линии 300 см (нижний край перекрытия),
    в любом ряду. Честно по камере такие вещи прятались бы за перекрытием, поэтому — так.
  - **Скрытая зона:** верх задней стены выше ~2,35 м закрыт перекрытием (камера смотрит сверху) — декор
    оболочки (трубы, решётки, щитки) ставим ниже.
- Типы комнат (как в игре): бункер — `entrance`, `shelter_living`, `kitchen`, `storage`, `workshop`, `water_room`,
  `machine_room`, `greenhouse`; дома — `house_living`, `bedroom`, `kitchen`, `bathroom`, `garage`, `office`, `shop`,
  `medical`.
- Состояния: `normal`, `abandoned` (пыль, паутина), `looted` (сорванные плакаты, мусор у стен),
  `damaged` (пробоины, обломки у стены — без провалов в полу). **Пыль, паутина, мусор — только формой или
  пятнами цвета палитры** (правило 10), не текстурой.
- Оболочки **темнее предметов** — иначе вещи теряются на фоне.

**Готовые расстановки (чтобы комнаты были «как задумано», а не случайные).** Комната собирается в Blender из оболочки
и отдельных предметов (`render/_room_preview.py`), а в игру отдаётся **не картинкой, а списком** — точные места
картинок посчитаны из 3D: `layouts/<имя>.json`, у каждого предмета `image` (имя картинки), `x_m` (середина от левого
края комнаты, м), `bottom_m` (низ картинки над линией пола, м; в игре ×100 px). Порядок в списке = порядок рисования.
Образец, как игра должна это рисовать, — `godot_test/room_demo/` (Godot, свет по картам нормалей).
Старый, упрощённый вариант (ряды) — ниже, для случайной расстановки. Файл
`layouts/<тип>_<имя>.json`: `{"room": "kitchen", "shell": "kitchen_tile_normal", "width_m": 6, "items":
[{"id": "fridge", "variation": "elektricheskiy", "state": "idle", "x_m": 0.6, "row": "back"}, …]}`
(`x_m` — середина предмета от левого края, `row` — `back` у стены, `mid`, `front`, `ceiling` — под потолком;
`variation`/`state` — какую картинку взять). Игра расставит по нему настоящие предметы. Пример —
`layouts/shelter_living_test.json`; как это выглядит — `python3 render/_mockup.py` (собирает комнату из картинок
ровно по этим правилам).
Это надо доделать в игре (см. `docs/FOR_GAME.md`).

## 3. Дома снаружи (фасады)

- Фасад дома на улице: ширина **560–860 см**, высота **300–420 см** (1 этаж) / **420–680 см** (2 этажа).
- Файлы: `facade_<тип>_<вариация>_<состояние>.png` — тип `house`, `shop`, `garage`…, состояние как у комнат
  (`normal`, `abandoned`, `looted`, `damaged`).
- Дверь фасада — **по центру** низа (вход), окна — по этажам. Крыша — часть фасада.
- Низ = земля, прозрачный фон.

## 4. Улица: дальние слои (параллакс)

- 3 слоя, **бесшовные** по горизонтали, низ = линия земли, сверху прозрачно; **неба не рисовать** (солнце, луна,
  облака, звёзды — игра):
  - `skyline_1` — дальний город на горизонте, 2048 × 600;
  - `skyline_2` — средний (мост, руины), 2048 × 500;
  - `skyline_3` — ближний (заборы, деревья, завалы), 2048 × 300.
- Дальние слои — светлее и синее (дымка), ближние — темнее и чётче.

## 5. Персонажи и животные

- Кадры анимации — **листом в строку**, все кадры одного размера:
  - человек — кадр **120 × 200 см**, ноги — по центру низа кадра; собака — **120 × 80 см**;
  - **линия земли — на 3 см (6 px рендера, 3 px в игре) выше низа кадра**: человек стоит серединой на глубине 0,
    носки ботинок (они ближе к камере) опускаются ниже — так они не обрезаются;
  - `survivor_base_walk.png` (8 кадров), `_idle` (4), `_work` (6), `_sleep` (2), `_sit` (2), `_hit` (4), `_hurt` (2),
    `_die` (6), `_carry` (8) — и к каждому `_n.png`.
- Смотрит **вправо**. Одежда — пока одна базовая (разная одежда на теле — только в пути Б).
- Портрет для экрана «Персонажи» — `portrait_<вариация>.png`, **400 × 500 px**, по пояс, та же палитра
  (здесь допускается лёгкий свет — это интерфейс, не мир).

## 6. Блоки земли (копание)

- `block_<id>.png` — клетка **100 × 100 см**, бесшовная со всех сторон (земля, камень, бетон, кирпич…).
- Вид — срез, ровно спереди (без наклона), плюс `_n.png`.

## 7. Чек-лист перед отдачей

- [ ] Камера из шаблона (наклон 12°, вертикаль +2,2 %), масштаб 200 px/м, модель — по размерам ОС.
- [ ] Чистый цвет без света и теней, цвета — только из палитры, Standard.
- [ ] Есть `_n.png` того же размера.
- [ ] Низ = пол, по центру; без полей (предметы) / точно по размеру (комнаты, фоны).
- [ ] Бесшовность (оболочки, перекрытия, слои улицы, блоки).
- [ ] Имя по правилам, файл в `renders/<категория>/`, отметка в `docs/OBJECTS.md`.
